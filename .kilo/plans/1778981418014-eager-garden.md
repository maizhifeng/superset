# Apache Superset 键盘快捷键方案

## 现状分析

- **依赖库**: `mousetrap` (v1.6.5) 已是项目依赖，目前仅在 SQL Lab 中使用
- **SQL Lab**: 拥有较完善的快捷键系统，通过 `KeyboardShortcutButton` 组件、`KEY_MAP` 枚举、`getHotkeyConfig()` 实现；快捷键包括 Ctrl+Enter、Ctrl+R、Ctrl+Shift+Enter、Ctrl+Shift+F 等
- **Dashboard**: `UndoRedoKeyListeners` 组件通过原生 `document.addEventListener` 处理 Ctrl+Z/Ctrl+Y
- **Explore**: 通过原生 `document.addEventListener` 实现 Ctrl+Enter 运行查询
- **无共享抽象层**: 每个模块各自独立实现快捷键处理
- **无集中式快捷键帮助**: 仅 SQL Lab 有快捷键对话框
- **无一致的跨平台处理**: 有基础的 `detectOS()` 检测但应用不一致

## 架构设计

### 1. 共享 Hook: `useShortcut` (`superset-frontend/src/hooks/useShortcut/`)

对 Mousetrap 的轻量封装：

```ts
// useShortcut.ts
function useShortcut(
  keybind: string | string[],
  handler: (event: ExtendedKeyboardEvent) => void,
  options?: { enabled?: boolean; scope?: string }
): void

// useShortcutWithHelp.ts — 扩展 useShortcut，增加帮助元数据
function useShortcutWithHelp(
  keybind: string | string[],
  handler: (event: ExtendedKeyboardEvent) => void,
  help: { label: string; category: string },
  options?: { enabled?: boolean; scope?: string }
): void
```

- 自动处理 mount/unmount 清理
- 支持跨平台按键归一化（Windows 上 Cmd→Ctrl，Mac 上 Ctrl→Cmd）
- 支持作用域（按模块启用/禁用快捷键）
- 可选地将快捷键注册到帮助注册表

### 2. 快捷键注册表 (`superset-frontend/src/hooks/useShortcut/shortcutRegistry.ts`)

一个单例，收集所有注册的快捷键以供帮助对话框使用：

```ts
interface ShortcutEntry {
  key: string;
  label: string;
  category: ShortcutCategory;
  module?: string;
}

interface ShortcutRegistry {
  register(entry: ShortcutEntry): () => void;
  getAll(): ShortcutEntry[];
  getByCategory(category: ShortcutCategory): ShortcutEntry[];
}

type ShortcutCategory =
  | 'global'       // 全局
  | 'navigation'   // 导航
  | 'sql_lab'      // SQL 实验室
  | 'explore'      // 探索（图表构建器）
  | 'dashboard'    // 仪表盘
  | 'list_view';   // 列表视图
```

### 3. 键盘快捷键帮助对话框

可复用的 React 组件，从注册表读取数据并按类别分组展示所有快捷键：

- `KeyboardShortcutHelpModal` — 通过 `?` 或 `Ctrl+/` 全局触发
- 与 SQL Lab 现有的 `KeyboardShortcutButton` 集成（重构以使用共享数据）
- 展示：类别 → 操作 → 按键组合 表格

## 实施计划

### 第一阶段：核心基础设施

**创建的文件：**
1. `superset-frontend/src/hooks/useShortcut/index.ts` — `useShortcut` hook 封装 Mousetrap
2. `superset-frontend/src/hooks/useShortcut/shortcutRegistry.ts` — 集中式注册表单例
3. `superset-frontend/src/hooks/useShortcut/constants.ts` — 快捷键常量、跨平台归一化
4. `superset-frontend/src/components/KeyboardShortcutHelpModal/index.tsx` — 可复用帮助对话框

**关键设计决策：**
- Mousetrap 已存在 — 复用它，而不是替换它
- Hook 自动按操作系统归一化按键（Ctrl vs Cmd）
- 注册表是纯模块级单例（无 Redux）— 轻量简洁
- 帮助对话框直接从注册表读取数据，无需通过组件树传递 props

### 第二阶段：模块重构

**SQL Lab：**
- 将 `SqlEditor/index.tsx` 中的 `getHotkeyConfig()` / `useEffect(Mousetrap.bind)` 迁移到 `useShortcut()` hooks
- 从 SqlEditor、App 中移除直接的 `Mousetrap` 导入（保留 App 卸载时的 Mousetrap.reset() 用于清理）
- 让 `KeyboardShortcutButton` 使用共享注册表替代自身的 `KEY_MAP`
- **统一 `KeyboardShortcut` 枚举**：从 `KeyboardShortcutButton/index.tsx` 移到共享的 `constants.ts`

**Dashboard：**
- 将 `UndoRedoKeyListeners/index.tsx` 从原生 `addEventListener` 转换为 `useShortcut()` hook（类组件 → 函数组件）
- 添加新快捷键（编辑模式、保存等）

**Explore：**
- 将 `ExploreViewContainer/index.tsx` 中的原生 `addEventListener('keydown', handleKeydown)` 替换为 `useShortcut()` hook
- 添加新快捷键（保存、切换面板等）

**列表视图：**
- 在共享的 `ListView` 组件（如果存在）或每个列表页面中添加 `useShortcut` 调用

### 第三阶段：全局导航

- 在 `views/App.tsx`（或 RootContextProviders）中添加全局快捷键层
- 注册全局导航快捷键
- 将快捷键注册表和帮助对话框接入应用外壳

### 第四阶段：打磨完善

- 验证模块快捷键与全局快捷键之间没有冲突
- 为 `useShortcut`、注册表和帮助对话框添加单元测试
- 为关键快捷键添加 E2E 测试（Playwright）
- 更新 SQL Lab 中的 `KeyboardShortcutButton`，使其反映所有已注册的快捷键（根据 UX 反馈决定是包含全部还是仅 SQL Lab）

## 快捷键提示策略（在恰当的时机予以提示，不干扰用户体验）

### 通用原则

- **新手引导 vs 效率工具**：快捷键提示面向已经熟悉界面、希望提升操作效率的用户。首次访问时不主动弹窗提示，仅在用户通过 `?` 触发时才展示帮助对话框
- **渐进式发现**：用户通过操作自然发现快捷键，而不是被强制学习

### 提示位置与时机

| 提示方式 | 触发时机 | 实现 |
|---------|---------|------|
| **工具提示 (Tooltip)** | 鼠标悬停在按钮上时 | 在主操作按钮（运行查询、保存、撤销等）的 `title`/`tooltip` 属性中附加快捷键文本，例如"运行查询 (Ctrl+Enter)" |
| **下拉菜单标注** | 用户打开菜单时 | 在菜单项右侧显示快捷键，与操作系统菜单惯例一致 |
| **空状态提示** | 页面首次加载、无数据时 | 在空状态区域展示快捷键提示，如"按 `?` 查看所有快捷键" |
| **Toast 提示** | 快捷键功能首次被触发时 | 用户第一次使用某个快捷键时，通过轻量 Toast 提示其对应功能名称，帮助建立关联记忆 |
| **帮助入口标记** | 始终可见（不 intrusive） | 在页面底部或导航栏一角放置固定入口按钮（如 `?` 图标），hover 时显示"快捷键 (Shift+?)" |

### 优先级（按实现紧迫性）

1. **主操作按钮 tooltip** — 投入产出比最高，用户悬停即可发现
2. **帮助入口标记** — 让用户知道快捷键功能存在
3. **菜单项标注** — 对齐操作系统惯例，用户期望在此看到
4. **空状态提示** — 低侵入性，仅在无内容时展示
5. **首次使用 toast** — 需增加使用计数逻辑，复杂度较高，可延后

### 反模式（避免的做法）

- 不要弹出模态框或大横幅引导用户学习快捷键
- 不要主动覆盖用户正在进行的操作来展示提示
- 不要在每次页面加载时都展示提示
- 不要高频重复同一提示（首次使用 toast 应只出现一次，可存入 localStorage）

## 非目标

- 不要构建完整的"自定义快捷键"UI（可作为下一阶段）
- 不要修改 Ace/CodeMirror 编辑器级别的快捷键系统
- 不要为快捷键标签添加 i18n（继续使用现有的 `t()` 模式）
- 不要为每个 UI 元素添加快捷键视觉提示（仅限主操作按钮的 tooltip）
