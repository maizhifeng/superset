# Dashboard Filter Module Design Plan

## Goal

Build a simple filter module in `superset-frontend-new/` using MUI's `SwipeableDrawer` (anchored top, sliding down). Filters are auto-discovered from the dashboard's native filter configuration OR generated from chart group-by dimensions.

## Architecture Overview

```
src/components/DashboardFilter/
├── types.ts                     — Filter-related type definitions
├── useDashboardFilters.ts       — Hook: discovers filters, manages state, builds extra query params
├── DashboardFilterDrawer.tsx    — SwipeableDrawer wrapper (anchor=top)
├── FilterPanel.tsx              — Drawer content: renders filter controls
├── FilterToggleFab.tsx          — FAB / toolbar button to open drawer
└── index.ts                     — Re-exports
```

## Data Source & Auto-Discovery

### Source 1: Native Filter Configuration (preferred)
From `dashboard.json_metadata` → parsed JSON → `native_filter_configuration[]`.
Each entry has: `id`, `name`, `filterType`, `targets[{datasetId, column:{name}}]`, `controlValues`, `defaultDataMask`, `chartsInScope`.

### Source 2: Chart Dimension Auto-Discovery (fallback / augmentation)
Iterate all charts in the dashboard, extract `groupby` / `columns` from each chart's `form_data`, deduplicate by `(datasource_id + column_name)`.

### Filter Types Supported (v1)
- **filter_select / value**: Multi-select Autocomplete (fetch distinct values via `/api/v1/dataset/{id}/values/?column={name}`)
- **text**: TextField with debounced input
- **numerical_range**: Min/Max number inputs
- **time_range**: Date range picker (MUI X DatePicker)

### Filter Effect on Chart Queries
When a filter value changes, generate `adhoc_filters` and append to every chart's data query:

```typescript
// Single-value filter
{ clause: 'WHERE', expressionType: 'SIMPLE', subject: columnName, operator: '==', comparator: value }
// Multi-value filter  
{ clause: 'WHERE', expressionType: 'SIMPLE', subject: columnName, operator: 'IN', comparator: values.join(',') }
```

These are merged into the `queries[0].adhoc_filters` array of the `POST /api/v1/chart/data` payload.

## Component Details

### `types.ts`
```typescript
interface FilterConfig {
  id: string;
  name: string;
  filterType: 'filter_select' | 'text' | 'value' | 'numerical_range' | 'time_range';
  datasetId: number;
  column: string;
  controlValues?: Record<string, any>;
  chartsInScope?: number[];
}

interface FilterState {
  [filterId: string]: {
    value: any;              // current selected value(s)
    extraFormData?: Record<string, any>;
  };
}
```

### `useDashboardFilters(dashboardJsonMetadata, charts, chartMeta)`
- Parses `native_filter_configuration` from json_metadata
- Falls back to extracting unique `(datasource_id, column)` pairs from chart form_data
- Returns:
  - `filters: FilterConfig[]` — discovered filter configurations
  - `filterState: FilterState` — current values for each filter
  - `setFilter(id, value): void` — update a filter's value
  - `clearAll(): void` — reset all filters
  - `buildAdhocFilters(): AdhocFilter[]` — build query filters from current state
  - `activeCount: number` — number of filters with non-empty values
  - `loading: boolean`

### `DashboardFilterDrawer`
```
<SwipeableDrawer
  anchor="top"
  open={open}
  onClose={onClose}
  onOpen={onOpen}
  slotProps={{ paper: { sx: { maxHeight: '60vh', borderBottomLeftRadius: 16, borderBottomRightRadius: 16 } } }}
>
  <FilterPanel filters={filters} filterState={filterState} onFilterChange={setFilter} onClearAll={clearAll} />
</SwipeableDrawer>
```

### `FilterPanel`
- Header: "Filters" title + close icon + "Clear all" link + active count badge
- Scrollable body: list of filter controls
  - Each control: label + appropriate input component
  - filter_select/value → `Autocomplete` (multiple, loading from API)
  - text → `TextField`
  - numerical_range → two `TextField` (min/max)
  - time_range → MUI X `DatePicker`
- Footer (collapsed by default): "Clear all" button

### `FilterToggleFab`
- IconButton with `FilterListIcon` placed in the dashboard header area (via BreadcrumbContext custom actions slot)
- Shows active filter count badge
- On click, opens the drawer

## Integration into Dashboard Page

### Changes to `src/pages/Dashboard/index.tsx`

1. **Import** the new filter hook and components
2. **Extract filter config** from `dashboard.json_metadata` after loading
3. **Render** `FilterToggleFab` in the header actions area (via BreadcrumbContext `setCustom`)
4. **Render** `DashboardFilterDrawer` with the filter hook state
5. **Integrate with chart data fetching**:
   - Create a function `getQueriesWithFilters(queries)` that merges active filter `adhoc_filters` into each query
   - Call it before each `POST /api/v1/chart/data` call
   - When filter state changes, re-fetch all charts

### Data Flow
```
Dashboard Load
    ↓
parse json_metadata → useDashboardFilters
    ↓                        ↓
display filters        user selects value
                           ↓
                      setFilter(id, value)
                           ↓
                      re-fetch charts with adhoc_filters
                           ↓
                      update chartData state
                           ↓
                      charts re-render with filtered data
```

## Integration Points (minimal changes to existing files)

### Fix 1: AppLayout doesn't consume BreadcrumbContext (critical bug)

**Root cause**: `BreadcrumbContext` is created and Dashboard calls `setCustom()` to set the dashboard title and actions (publish chip, filter toggle), but **`AppLayout.tsx` never reads from this context**. The breadcrumbs are rendered purely from `location.pathname`. As a result, the dashboard title override and all custom actions (including FilterToggleFab) are invisible.

**Fix in `src/components/AppLayout.tsx`**:
- Import `useBreadcrumb` from `@/contexts/BreadcrumbContext`
- After the existing breadcrumb items, render:
  - If `custom` has a `label`, show it as the last breadcrumb
  - If `custom` has `actions`, render them next to the breadcrumbs

### Fix 2: Add persistent swipe handle below AppBar, fix drawer position

**The swipe handle (horizontal bar) must be visible even when the drawer is closed**, as a persistent visual indicator below the AppBar.

**In `src/pages/Dashboard/index.tsx`**:
- Remove the `<Fab>` / floating FAB block (previously added, already removed above)
- Remove unused imports: `Fab`, `Badge` from @mui/material, `FilterListIcon` from @mui/icons-material
- Add a permanent `FilterHandle` component rendered directly below the AppBar:

```tsx
{/* Persistent swipe handle — always visible below AppBar */}
<Box
  onClick={() => setFilterDrawerOpen(true)}
  sx={{
    position: 'fixed',
    top: '48px',
    left: '50%',
    transform: 'translateX(-50%)',
    zIndex: 1099,
    display: 'flex',
    flexDirection: 'column',
    alignItems: 'center',
    cursor: 'pointer',
    pt: 0.5,
    pb: 0.25,
    px: 2,
    '&:hover': { opacity: 0.8 },
  }}
>
  <Badge
    badgeContent={activeCount}
    color="primary"
    overlap="circular"
    slotProps={{ badge: { sx: { height: 14, minWidth: 14, fontSize: 9, top: 2 } } }}
  >
    <Box
      sx={{
        width: 40,
        height: 4,
        borderRadius: 2,
        bgcolor: 'grey.400',
        transition: 'background-color 200ms',
      }}
    />
  </Badge>
</Box>
```

This renders a small gray pill (40×4px) centered below the AppBar, with an optional filter count badge. It's always visible regardless of drawer state. Clicking it opens the filter drawer.

**In `src/components/DashboardFilter/DashboardFilterDrawer.tsx`**:
- Add `top: '48px !important'` to `slotProps.paper.sx` so the drawer appears just below the AppBar  
- Keep the existing swipe handle bar inside the drawer for when it's open

The `FilterToggleFab` in AppBar toolbar (via `BreadcrumbContext`) will remain as a secondary trigger. The primary visual trigger is the persistent handle bar below the AppBar.

### Fix 3: Chart API may not include `form_data`

**Issue**: The chart list endpoint at `/chart/?q=(page_size:200,page:0)` may not include `form_data` in the default response. Without `form_data`, the fallback dimension auto-discovery from chart `groupby`/`columns` won't work.

**Fix**: The `useDashboardFilters` hook should also read the dashboard's `json_metadata.native_filter_configuration` as the primary source. If that's empty and chart form_data is also unavailable, show a helpful "No filters configured" message instead of silently showing nothing.

## Edge Cases & Considerations

- **Filters with no context (scope)**: Only apply a filter to charts that reference the same dataset+column
- **Loading state**: Fetch distinct values asynchronously when filter panel opens
- **Performance**: Debounce filter changes before re-fetching all charts (300ms)
- **Empty state**: "No filters configured" message when no dimensions found
- **Error state**: Graceful handling when value fetch API fails
- **Mobile responsive**: Drawer takes full width on small screens
- **Swipeable edge**: Drawer anchored top slides down from under the AppBar (`top: 48px`), with visible swipe handle bar at top of the drawer panel
- **Trigger location**: Filter icon button in AppBar toolbar (right side, near breadcrumbs/account avatar), rendered via BreadcrumbContext custom actions
