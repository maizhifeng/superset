# 优化计划：superset-frontend-new

## 概述

`superset-frontend-new/` 目录是 Apache Superset 前端的全新重写，使用 **Vite + MUI + Zustand**。约 10,700 行代码，112 个 TS/TSX 文件，是一个精简但快速增长的代码库。以下是具体的优化机会。

---

## 1. 移除未使用的依赖（package.json）

### 影响：减少打包体积，加快安装速度

| 未使用的包 | 原因 |
|---|---|
| `@reduxjs/toolkit`、`redux`、`react-redux`、`reselect` | 已被 zustand 替代 |
| `@apache-superset/core` | 未在 `src/` 中任何地方导入 |
| `@superset-ui/core` | 未在应用代码中导入 |
| `@superset-ui/chart-controls` | 未导入 |
| `ag-grid-community`、`ag-grid-react` | 未导入 |
| `react-dnd`、`react-dnd-html5-backend` | 未导入 |
| `react-resizable` | 未导入（`react-grid-layout` 有在使用） |
| `re-resizable` | 未导入 |
| `dom-to-image-more` | 未导入 |
| `use-immer` | `immer` 有直接使用，但这个 hook 没有 |

**操作：** 从 `package.json` 中移除这些依赖，然后运行 `npm install` 清理。

---

## 2. 清理空目录/死目录

### 影响：提高开发者清晰度，减少范围蔓延

空目录：
- `src/features/` — 24 个空子目录（alerts、charts、dashboards 等）
- `src/middleware/` — 空
- `src/setup/` — 空
- `src/extensions/` — 空
- `src/types/` — 空
- `src/logger/actions/` — 空
- `.storybook/shared/` — 空

**操作：** 移除空目录，如需保留占位则添加 `.gitkeep`。

---

## 3. 简化状态管理

### 影响：降低复杂度，减少不必要的重新渲染

- **`ToolbarProvider`** 是一个空操作组件（直接返回 `{children}`）— 可以完全移除；`useToolbarStore` zustand store 可以独立工作。
- **`AuthContext`** 包装了 zustand 的 `useAuthStore` — 消费组件可以直接调用 `useAuthStore`，移除这一层 context。
- **`BreadcrumbContext`** — 同上。这些 context provider 增加了不必要的 React 树深度。

**操作：** 移除 `ToolbarProvider`、`BreadcrumbContext` 和 `AuthContext` 包装器；直接使用 zustand store。

---

## 4. 提取共享模式（DRY）

### 影响：减少约 30% 的重复代码

| 模式 | 位置 | 重构目标 |
|---|---|---|
| **内联表格渲染**（使用 JSX IIFE 的 headers/rows/keys） | `ChartEditor.tsx`、`ChartCard.tsx` | 提取可复用的 `DataPreviewTable` 组件 |
| **ECharts 类型加载**（`ensureChartType` + `chartLibReady` 状态） | `ChartEditor.tsx`、`ChartCard.tsx` | 提取自定义 hook `useEChartsType(vizType)` |
| **rison.encode + 分页 API 获取** | 8 个列表页面 | 提取 `usePaginatedList(queryKey, endpoint)` hook |
| **错误显示模式**（`err instanceof Error ? err.message : ...`） | 约 10 个文件 | 提取 `parseErrorMessage(err)` 工具函数 |
| **Dashboard 布局扁平化**（`flattenLayout`、`getChildWidth`） | `Dashboard/index.tsx` | 提取到 `utils/dashboard/layout.ts` |

**操作：** 将每个模式提取为可复用的 hooks/组件/工具函数。

---

## 5. 性能优化

### 影响：更流畅的交互，更少的不必要计算

- **`Dashboard/index.tsx` 有 637 行**，20+ 个 useState/useEffect hooks。拆分为：
  - `DashboardPage.tsx` — 数据获取、布局状态
  - `DashboardGrid.tsx` — react-grid-layout 渲染
  - `DashboardToolbar.tsx` — 工具栏注册
  - `DashboardNav.tsx` — 图表导航对话框
- **Dashboard 的 `loadDashboard`** 使用 `useCallback` 包装，依赖项只有 `[id]` — 如果 `id` 字符串引用每次渲染都变化，会导致重复请求。使用 `useMemo` 稳定引用或直接传递 `id`。
- **在所有列表页面中添加搜索防抖**（目前每次按键都触发 API 请求）。
- **虚拟化大表格数据** — 将 ChartEditor 中的 `.slice(0, 50)` 和 ChartCard 中的 `.slice(0, 100)` 替换为 `@tanstack/react-virtual` 或 MUI 内置的虚拟化行。
- **移除 Dashboard 中重复的 ResizeObserver + window resize 监听器**（在同一个 effect 中同时绑定了两者）。
- **稳定化 `supportedVizTypes` Set** — 目前每次渲染都重新创建（在组件体内，第 231 行）。

---

## 6. 类型安全改进

### 影响：更好的 IDE 支持，更少的运行时错误

- **内联 API 响应类型**（例如 8 个地方的 `DashboardData`、`ChartData`）→ 统一到 `src/types/api.ts`
- **将 `Record<string, unknown>`** 替换为适当的类型接口
- **将 `(err as any).response?.data?.message`** 替换为类型化的错误工具函数
- **为 `api.get<T>()` 调用添加适当的泛型**（目前是内联类型或无类型）

---

## 7. 打包体积优化

### 影响：更快的页面加载

- **ECharts**：Dashboard 导入 `import * as echarts from 'echarts/core'` — tree-shaking 只保留使用的图表类型（line、bar、pie 等）
- **`@mui/x-data-grid`**（体积较大的包）→ 仅在 2 个组件中使用。考虑更轻量的替代方案或懒加载。
- **`superset-ui-mui/components/` 中的 93 个 MUI 包装组件** — 可能有大量未使用的组件。审计并移除死的组件。
- **`echarts-for-react/lib/core`** 导入是正确的（可 tree-shaking），但需要验证未使用的 ECharts 组件没有被打包。

---

## 8. 测试基础设施

### 影响：代码质量，防止回归

- **测试文件数量为 0**。为以下内容添加 vitest 测试文件：
  - `ChartEditor.tsx` 中的 `autoSuggestChartType()` 逻辑
  - `Dashboard/index.tsx` 中的 `flattenLayout()`
  - Zustand stores（简单的单元测试）
  - 使用 `@testing-library/react` 测试关键组件

---

## 9. 代码质量与可维护性

### 影响：降低认知负荷，一致的模式

- **Dashboard 组件（637 行）**：拆分为更小的文件
- **ChartEditor（669 行）**：拆分为更小的文件
- **AppLayout（447 行）**：拆分为更小的文件
- **替换字符串主题引用**，如 `'rgba(32, 167, 201, 0.08)'` 改为主题 token 引用
- **避免在 sx 属性中使用 `@keyframes`** — 移到共享的 keyframes 或 styled components
- **所有页面都使用相同的 skeleton/empty/error 分类模式** — 提取 `ListPageLayout` 包装组件
